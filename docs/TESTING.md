# Judge smoke test

Use this three-minute walkthrough to see the core WebMCP and accessibility features. No mouse is required.

## Setup

1. Open the app in a WebMCP-enabled Chromium browser with a browser agent or Model Context Tool Inspector connected.
2. Use a fresh, non-duplicated tab so the workflow starts at revision `0` with no change history.
3. Optional: start VoiceOver on macOS or NVDA on Windows before beginning.

## 1. Check keyboard access (30 seconds)

Press `Tab` once. Focus should land on **Skip to workflow workspace** with a visible outline. Activate it, then continue tabbing through the canvas.

You should encounter five clearly named workflow nodes:

- **Start node: Order received**
- **Action node: Fetch Orders**
- **Action node: Save Results**
- **Action node: Alert Team**
- **End node: Complete**

The **Zoom In**, **Zoom Out**, and **Fit View** controls are also keyboard accessible. With a screen reader, the page exposes a **Workflow editor** heading, a **Workflow canvas**, and a **Change history** heading.

## 2. Ask the agent to edit the workflow (60 seconds)

Give the connected agent this exact request:

> Inspect the workflow. Add a Retry node with three attempts after Fetch Orders, route Retry success to Save Results and Retry failure to Alert Team, and then show me the edit result.

The agent should discover the current revision, make one atomic edit, and focus the application-authored receipt in **Change history**.

Look or listen for:

- **Created Retry and changed 4 connections. Workflow validation passed.**
- A new **Retry** node showing **3 attempts**.
- One concise receipt marked **completed** and **unreviewed**.
- **Reveal Retry**, **Mark reviewed**, and **Undo** controls.

With VoiceOver or NVDA running, the change summary should be announced automatically and the receipt heading should receive focus. The receipt is proof generated by the application, not prose invented by the agent.

## 3. Verify agent-to-user focus handoff (30 seconds)

Ask the agent:

> Show the Retry workflow node.

The canvas should bring Retry into view, select it, and move keyboard focus to it. A screen reader should announce **Retry node: Retry**.

Then ask:

> Put keyboard focus on the Zoom In control.

When you return to the page and make your first keyboard or screen-reader interaction, focus should land on **Zoom In** exactly once. Later interactions should not pull focus back unexpectedly.

## 4. Review and undo without a mouse (60 seconds)

Return to the receipt, then use `Tab`, `Enter`, or `Space` to:

1. Activate **Reveal Retry** and confirm the canvas centers and selects Retry without moving focus away from the button.
2. Activate **Mark reviewed** and confirm the receipt changes from **Unreviewed** to **Reviewed**.
3. Activate **Undo**.

After Undo:

- A screen reader announces **Undid the previous workflow change and restored 4 connections. Workflow validation passed.**
- Focus returns to the original receipt heading.
- Retry disappears and the original Fetch Orders-to-Save Results connection returns.
- A new receipt records the undo, and the original Undo action is no longer available.

## Pass criteria

The smoke test passes if the agent can discover, edit, reveal, focus, and undo through WebMCP; the app records deterministic receipts; and the complete review path works with only a keyboard, with meaningful names, stable focus, and live screen-reader announcements.
